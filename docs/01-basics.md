# Go 初级阶段：语法基础

> 本阶段对应目录 `01-basics/`，共 10 个可独立运行的示例文件。
> 适合零基础读者，建议按文件编号顺序学习，每个文件先读注释、再 `go run` 运行、最后做本节的动手练习。

## 一、本阶段学习目标

学完这 10 个文件，你应当能够：

1. **理解 Go 程序的基本结构**：`package main`、`import`、`func main()` 三件套，知道 `go run` 与 `go build` 的区别。
2. **熟练使用变量、常量与基本类型**：`var` / `:=` / `const` / `iota`，理解零值与作用域，掌握显式类型转换。
3. **掌握流程控制与函数**：`if`、`for` 三种写法、`switch`、`range`、多返回值、`defer` 的 LIFO 顺序。
4. **理解数组、切片、map 的内存语义**：数组是值类型会整体拷贝；切片是"指针 + 长度 + 容量"；map 遍历无序且并发不安全。
5. **搞懂指针与字符串/rune**：`&` 取地址、`*` 解引用、值接收者与指针接收者的选择；字符串不可变、`len` 返回字节数、range 按 rune 解码。

## 二、环境准备与运行方式

### 1. 安装 Go

- 前往 Go 官网（https://go.dev/dl/）下载安装包，**Go 1.22 及以上版本均可**，本项目按 **Go 1.27.1** 编写。
- 安装完成后打开终端，验证安装：

```powershell
go version
# 预期输出类似：go version go1.27.1 windows/amd64
```

### 2. 运行任意示例文件

在**项目根目录** `D:\Project\gogogo` 下执行：

```powershell
go run 01-basics/01_hello.go
```

把文件名换成任意想学的文件即可，例如 `go run 01-basics/07_maps.go`。

### 3. 为什么每个文件都能独立运行？

- 每个 `.go` 文件第一行都有构建标签 `//go:build ignore`。
- 每个文件都是**独立的 `package main`**，且各自带一个 `func main()`。
- `//go:build ignore` 的作用：让 `go build ./...` 这类"整包构建"命令**跳过**这些文件——否则同目录下 10 个文件都有各自的 `main` 函数，一起编译必然冲突。
- 而 `go run 单个文件.go` 会忽略该标签，所以可以正常运行。
- 因此，如果你在项目根目录执行 `go build ./...`，看到 **"matched no packages" 的提示是预期行为**，不是错误——它恰恰说明构建标签生效了。

### 4. 格式化建议

Go 有官方格式化工具 `gofmt`，建议让编辑器保存时自动调用（VS Code / GoLand 装 Go 插件后默认开启），也可以手动执行：

```powershell
gofmt -w 01-basics/01_hello.go
```

另外推荐偶尔跑一下 `go vet <文件>`，它能静态检查出 `Printf` 动词与参数不匹配等常见错误。

## 四、逐文件详解

### 01_hello.go：程序结构与第一个程序

**这个文件带你认识什么**

这是整个系列的起点。你将看到最小 Go 程序的三个组成部分（`package main`、`import "fmt"`、`func main()`），分清 `Println`、`Print`、`Printf` 三种打印方式的区别，学会 `%d %s %v %T %q` 这五个最常用的格式化动词，并理解 `go run` 和 `go build` 分别适合什么场景。

**运行命令与预期输出解读**

```powershell
go run 01-basics/01_hello.go
```

输出按 5 个示例分段，每段前有 `========== 示例 N ==========` 分隔：

- **示例 1**：打印程序结构说明和 "Hello, Go!" 问候语。
- **示例 2**：对比三种打印函数——`Println` 自动加空格并换行；两次 `Print` 的内容连成一行；`Printf` 按格式串输出"我叫小明，今年18岁"。
- **示例 3**：逐行展示各格式化动词的效果，例如 `%d` 输出 42、`%T` 输出类型名、`%q` 把含换行的字符串连引号一起显示出来、`%.2f` 保留两位小数。
- **示例 4**：用文字说明 `go run` 与 `go build` 的区别，以及 `//go:build ignore` 的作用。
- **示例 5**：演示 `Sprintf`/`Sprintln` 返回字符串、整数的十六进制/二进制/八进制输出、宽度对齐（`%5d`、`%-5d`、`%05d`），最后特意演示动词多于参数时出现 `%!d(MISSING)` 怪输出的情况。

**关键代码讲解**

```go
name := "小明"
age := 18
fmt.Printf("Printf：我叫%s，今年%d岁。\n", name, age)
```

`Printf` 的第一个参数是格式串，其中的 `%s`、`%d` 叫"动词"，会被后面的参数**按顺序**替换。`Printf` 不自动换行，所以格式串通常以 `\n` 结尾。

```go
fmt.Printf("%v  默认格式      -> %v / %v / %v\n", 3.14, true, []int{1, 2, 3})
```

`%v` 是"万能动词"，几乎什么类型都能以默认格式打印。初学时不知道该用哪个动词，就用 `%v` 兜底。

```go
//go:build ignore
```

文件第一行的构建标签让整包构建命令跳过本文件。因为同目录下多个示例各有自己的 `main` 函数，一起编译会冲突；而 `go run 单个文件` 会忽略这个标签，两者互不干扰。

**常见坑/易错点**

1. **import 了却没使用会编译报错**（"imported and not used"）。这是 Go 的刻意设计，删掉没用的 import 即可。
2. **`fmt.Print` 拼接纯字符串时不加空格也不换行**——它只在相邻参数都不是字符串时才插空格，连续 `Print` 几个字符串很容易连成一片。
3. **`Printf` 动词与参数个数不匹配不会编译报错**，而是输出 `%!d(MISSING)` 之类的怪字符串，只能靠肉眼（或 `go vet`）发现。
4. **`func main` 不能带参数、不能有返回值**，这与 C/Java 不同；需要命令行参数要用 `os.Args`（后续章节内容）。

**动手练习**

1. 在示例 3 后面加一行，用 `%T` 打印变量 `3.14`、`true`、`[]int{1}` 的类型。（提示：参照文件中 `%T` 的既有写法。）
2. 修改示例 2，故意让 `Printf` 的动词比参数多一个，运行观察 `%!d(MISSING)` 输出，加深印象。

### 02_variables.go：变量与常量

**这个文件带你认识什么**

学习 Go 中声明数据的两种方式：`var`（通用）和 `:=`（函数内简写），以及编译器的类型推断。你还会认识常量 `const` 和枚举计数器 `iota`，理解"零值"这个 Go 特有的安全保证，以及由花括号决定的变量作用域和"遮蔽"现象。

**运行命令与预期输出解读**

```powershell
go run 01-basics/02_variables.go
```

- **示例 1**：打印用 `var` 声明的一组变量（name、age、city、isActive）以及两个包级变量的值。
- **示例 2**：打印 `score=95.5` 及其推断出的类型；演示一行交换 `x, y`；演示 `a, b := 2, 3` 这种"左边有新变量即可"的混合声明。
- **示例 3**：打印常量 pi、appName；用 iota 定义的星期枚举（Monday=0 … Friday=4）；用 `1 << (10 * iota)` 定义的 KB/MB/GB（1024、1048576、1073741824）。
- **示例 4**：打印 int、float64、bool、string 的零值（0、0、false、""）。
- **示例 5**：演示函数级变量、块级变量的可见范围，以及内层同名变量"遮蔽"外层变量时内外打印结果不同。

**关键代码讲解**

```go
a := 1
a, b := 2, 3 // b 是新变量，所以合法；a 是重新赋值
```

`:=` 要求左边**至少有一个新变量**，否则报 "no new variables on left side of :="。上面第二行里 `b` 是新的，所以合法，而 `a` 只是被重新赋值。

```go
const (
	_  = 1 << (10 * iota) // 忽略第 0 行
	KB                    // 1 << 10 = 1024
	MB                    // 1 << 20
	GB                    // 1 << 30
)
```

`iota` 是常量组内的"行号计数器"，从 0 开始逐行加一；后续行省略表达式时自动沿用上一行的表达式。配合位移运算可以优雅地定义字节单位。

```go
shadow := "外层"
{
	shadow := "内层" // 这是一个新变量，不是修改外层
}
```

内层块里用 `:=` 声明同名变量会**遮蔽**外层变量——出块后外层变量原样不变。这是常见 bug 来源：你以为改了外层，其实改的是内层的副本。

**常见坑/易错点**

1. **`:=` 不能用于包级变量**，函数外只能写 `var`。
2. **同一作用域内不能对同一变量重复 `:=`**，报 "no new variables on left side of :="。
3. **遮蔽（shadowing）是隐蔽 bug 来源**：内层修改的并不是你以为的那个变量。
4. **常量一旦声明就不能赋值**，给 `pi` 重新赋值会编译报错。

**动手练习**

1. 用 iota 定义一组"季节"常量（春夏秋冬，从 1 开始而不是 0）。（提示：第一行写 `Spring = iota + 1`。）
2. 写一段代码验证零值：声明 `var ok bool` 和 `var msg string` 不初始化，用 `%t` 和 `%q` 打印出来。

### 03_types.go：基本类型与类型转换

**这个文件带你认识什么**

认识 Go 的基本类型（int 系列、uint、float32/float64、bool、string），理解 Go **没有隐式类型转换**、一切转换都要显式写出。重点区分 `rune`（int32 别名，一个 Unicode 码点）和 `byte`（uint8 别名），区分"类型别名"与"自定义类型"这一等号之差，并学会用 `strconv` 包做字符串与数值的互转及错误检查。

**运行命令与预期输出解读**

```powershell
go run 01-basics/03_types.go
```

- **示例 1**：逐个打印各基本类型的值与类型；注意 `len("你好，Go")` 输出 **11**（字节数，不是字符数——3 个中文共 9 字节加上 "Go" 2 字节）。
- **示例 2**：演示 `float64(i) + f` 显式转换；`int(3.99)` 截断为 3（不是四舍五入）；`int8(300)` 溢出截断得到 44；`string(65)` 得到字符 "A" 而不是 "65"。
- **示例 3**：打印 `"Go语言"` 的字节长度和下标 0 处的 byte 值；用 `for range` 按 rune 遍历，注意索引是字节下标（0,1,4,7）会跳跃。
- **示例 4**：别名 `MyInt = int` 可直接与 int 相加；自定义类型 `Celsius`、`Fahrenheit` 必须显式转回 `float64` 才能相加。
- **示例 5**：演示 `Itoa`、`Atoi`（含转换失败的错误分支）、`ParseInt("ff", 16, 64)`、`FormatInt`、`ParseFloat` 的用法。

**关键代码讲解**

```go
sum := float64(i) + f
truncated := int(f) // 3.99 -> 3，截断而非四舍五入
```

Go 没有隐式类型转换，连 `int + float64` 都编译报错，必须显式 `T(v)`。浮点转整数直接**截断**小数部分，要四舍五入需自行处理。

```go
type MyInt = int      // 别名：同一个类型的另一个名字
type Celsius float64  // 自定义类型：全新类型，与 float64 不能直接混算
```

**有没有等号，语义天壤之别**：别名是"改名"，编译器完全视为一体；自定义类型是"新类型"，给相同底层数据赋予不同语义，让编译器帮你拦住"摄氏加华氏"这类 bug。

```go
num, err := strconv.Atoi("456")
if err != nil {
	fmt.Println("转换失败：", err)
}
```

`Atoi` 返回两个值：结果和 error。Go 不抛异常，错误作为返回值显式检查。**忽略 err 是新手最常见的 bug 之一**——转换失败时结果是零值 0，会被当成正常结果用。

**常见坑/易错点**

1. **`len` 对字符串返回字节数**：UTF-8 下一个汉字占 3 字节，`len("你好，Go")` 是 11 不是 5。
2. **大范围转小类型溢出截断，Go 不会报错**：`int8(300)` 得到 44，悄无声息。
3. **`string(65)` 是码点转换**，得到字符 "A" 而非字符串 "65"；数值转字符串请用 `strconv.Itoa`。
4. **忽略 `Atoi` 的 err**：转换失败时 num 为 0，不检查就会把 0 当正常值。

**动手练习**

1. 用 `strconv.ParseInt` 以 2 进制解析 `"1010"`，打印结果（应为 10）。（提示：第二个参数填进制 2，位宽 64。）
2. 定义自定义类型 `type Meter float64` 和 `type Kilometer float64`，尝试直接相加观察编译错误，再改成显式转换后相加。

### 04_control.go：流程控制

**这个文件带你认识什么**

Go 的流程控制关键字很少：`if`、`for`、`switch` 三个就够，没有 `while`、没有 `do-while`。你将学会 `if` 的初始化语句、`for` 的三种写法、`switch` 的三种用法（含 `fallthrough`）、`range` 遍历各种集合，以及用 label 从多层嵌套循环中整体跳出。

**运行命令与预期输出解读**

```powershell
go run 01-basics/04_control.go
```

- **示例 1**：打印"及格：85"；用 `if remainder := score % 10; ...` 打印个位数是 5。
- **示例 2**：三段式 for 打印 `0 1 2`；条件式 for（类似 while）打印 `1 3 9`；无限循环打印两轮后在第 3 轮 `break` 退出。
- **示例 3**：day=3 命中"工作日"；score=72 命中"及格"；fallthrough 示例打印"二（从这里 fallthrough）"后被强制执行"三"。
- **示例 4**：range 遍历切片打印索引和水果名；只取值遍历；遍历 map 打印姓名和年龄（**输出顺序可能不同**——map 遍历顺序被故意随机化）；遍历字符串 "Go" 打印字节下标和字符。
- **示例 5**：`break OuterLoop` 在 `i*j >= 4` 时直接终止外层循环；`continue ContinueLoop` 在 `j == 2` 时跳过外层当前轮。

**关键代码讲解**

```go
if remainder := score % 10; remainder == 0 {
```

`if` 支持"初始化语句"：变量 `remainder` 只在 if/else 块内有效，出了分支就销毁。好处是作用域被限制在分支里，不污染外层。

```go
switch {
case score >= 90:
	fmt.Println("优秀")
case score >= 60:
	fmt.Println("及格")
}
```

无表达式 `switch` 的 case 里直接写布尔条件，等价于一串 `if-else if` 但更可读。注意 Go 的 case **默认自动 break**，不会像 C 那样穿透；要穿透须显式写 `fallthrough`。

```go
OuterLoop:
	for i := 1; i <= 3; i++ {
		for j := 1; j <= 3; j++ {
			if i*j >= 4 {
				break OuterLoop // 直接终止外层循环
			}
		}
	}
```

普通 `break` 只能跳出最内层循环。给外层循环贴 label（名字 + 冒号，独占一行）后，`break OuterLoop` 可以一次跳出多层；`continue` 同理。

**常见坑/易错点**

1. **`if` 条件必须是 bool**：写 `if 1 {}` 直接编译报错，这与 C 的 0/非 0 约定不同。
2. **`for {}` 里忘记 `break` 就是死循环**，程序永远不会退出。
3. **range 遍历时声明了索引却不用会编译报错**——只要值就用 `for _, v := range` 显式丢弃索引。
4. **`fallthrough` 无条件执行下一个 case 的语句体**，不看下一个 case 的条件，很少用但见到要认得。
5. **map 的 range 遍历顺序是故意随机的**，不能依赖输出顺序。

**动手练习**

1. 用"条件式 for"（类似 while 的写法）计算 1 加到 100 的和并打印。（提示：`for sum 控制条件 { ... }`，在循环体内累加。）
2. 写一个无表达式 switch，把百分制分数（0~100）映射为 优秀/良好/及格/不及格 四档。

### 05_functions.go：函数

**这个文件带你认识什么**

Go 函数最有特色的四个能力：天然支持多返回值（配合 error 构成标准错误处理模式）、命名返回值与裸 return、可变参数 `...int`、以及"函数是一等公民"（可赋值、可作参数、可作返回值）。最后深入讲解 `defer`：LIFO 执行顺序、注册时参数已求值、defer 可以修改命名返回值。

**运行命令与预期输出解读**

```powershell
go run 01-basics/05_functions.go
```

- **示例 1**：打印 `divide(10, 3)` 的商 3 余 1；`safeDivide(10, 2)` 正常返回 5；`safeDivide(10, 0)` 走错误分支打印"除数不能为 0"。
- **示例 2**：`splitSum([]int{80, 90, 100})` 打印 total=270、avg=90.00。
- **示例 3**：分别打印 `sumAll()`（0）、`sumAll(1)`、`sumAll(1,2,3,4)`（10）、`sumAll(nums...)`（切片展开传入，18）。
- **示例 4**：函数赋值给变量、`apply(3, 4, multiply)` 回调（12）、`getOperator("add")` 返回函数再调用（7）、匿名函数求平方（36）。
- **示例 5**：函数体正常输出先打印；`deferredReturn()` 打印 1（defer 把 0 改成了 1）；模拟资源打开/使用/关闭的三行输出；`defer` 捕获的 x 打印 1 而非 100。**注意 defer 的输出顺序：示例 5 里三个 defer 按"最后注册的最先执行"（LIFO），会在函数体所有正常输出之后、函数返回前倒序打印。**

**关键代码讲解**

```go
func safeDivide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("除数不能为 0")
	}
	return a / b, nil
}
```

Go 的标准模式：**最后一个返回值是 error**，调用方必须先检查 `err != nil` 再使用结果。`nil` 表示"没有错误"。

```go
defer fmt.Println("defer 1：最先注册，最后执行")
defer fmt.Println("defer 2")
defer fmt.Println("defer 3：最后注册，最先执行")
```

多个 defer 按 **LIFO（后进先出）** 顺序执行：先注册的最后执行。典型用途是资源释放——打开资源后立刻写 defer 关闭，无论函数从哪个分支返回都会执行。

```go
x := 1
defer fmt.Println("defer 捕获的 x =", x) // 注册时 x=1 已定
x = 100
```

**defer 的参数在注册时就已求值**，不是执行时才求值。所以这里打印的是 1 而不是 100。

```go
func deferredReturn() (result int) {
	defer func() { result++ }()
	return 0 // 先赋 0，defer 再把它改成 1
}
```

defer 在 `return` 赋值之后、函数真正退出之前执行，因此可以修改**命名返回值**——这个函数实际返回 1。

**常见坑/易错点**

1. **声明了变量不用会编译报错**——这逼着你不能"假装没看见"错误返回值；不关心的值用 `_` 丢弃。
2. **裸 return 存在争议**：短函数简洁，长函数中"到底返回了什么"要翻回签名查看，复杂函数请显式 `return total, avg`。
3. **可变参数必须是参数列表最后一个，且最多一个**；传已有切片时用 `切片...` 展开。
4. **defer 参数注册时求值**：想在 defer 里拿到变量的"最新值"，要用闭包包裹而不是直接传参。
5. **defer 顺序是 LIFO**，理解错顺序会误判资源释放/日志输出的先后。

2. 写三个 defer 语句注册顺序为 A、B、C，预测并运行验证实际输出顺序是 C、B、A。

### 06_arrays_slices.go：数组与切片

**这个文件带你认识什么**

这是初级阶段最重要的内存语义课。**数组是值类型**——赋值和传参都整体拷贝；**切片是"指向底层数组的指针 + 长度 len + 容量 cap"三要素**，多个切片可以共享同一个底层数组。你将观察 `append` 的扩容行为、`copy` 的用法，以及"共享底层数组"这个 Go 新手几乎必踩的坑和两种防御手段。

**运行命令与预期输出解读**

```powershell
go run 01-basics/06_arrays_slices.go
```

- **示例 1**：数组 `b := a` 后改 `b[0]`，`a` 不受影响仍是 `{1 2 3}`；把数组传给函数修改同样无效；传指针 `&a` 后修改才真正生效。
- **示例 2**：打印切片 `s` 及其子切片 `sub := s[1:3]` 的 len/cap——`sub` 长度 2 但容量 3（底层数组从起始位置起还有空间）；`make([]int, 0, 8)` 创建长度 0、容量 8 的切片。
- **示例 3**：从容量 2 开始连续 append 5 个元素，每次容量不足时打印扩容过程（容量不足时 append 申请更大的新底层数组），最后打印完整切片。
- **示例 4**：`copy(dst, src)` 复制 5 个元素，改 `dst[0]` 不影响 `src`；演示用 `copy(s[1:], s[2:])` + 截短长度来"删除"下标 1 的元素。
- **示例 5**：子切片 `part := original[1:3]` 改 `part[0]` 直接影响 `original`；更隐蔽的是 `part` 容量为 4，前两次 append **不扩容**，悄悄覆盖 `original` 下标 3、4 的元素；append 到 len 超过 cap 4 才扩容换新数组，此后与原数组彻底分离。最后演示两种防御：copy 出独立副本、三索引切片 `original[1:3:3]` 限制容量。

**关键代码讲解**

```go
b := a // 数组赋值会整体拷贝，b 是一份独立副本
b[0] = 100
```

`a` 不受影响——数组是**值类型**，赋值、传参都会整体拷贝。想改原数组必须传指针（`modifyArrayByPtr(&a)`）。

```go
sub := s[1:3] // len=2，但 cap=3
```

切片的容量是"底层数组从子切片起始位置起还能容纳多少"。`sub` 虽然只看得见 2 个元素，容量却有 3——这正是示例 5 那个坑的根源。

```go
s = append(s, i) // 必须把返回值赋回变量
```

append 容量不足时会申请一块**更大的新底层数组**，返回的可能是指向新数组的切片。所以错误写法 `append(s, 6)`（不接返回值）会悄悄丢失结果，`s` 毫无变化。

```go
safe := original[1:3:3] // 三索引切片，把容量显式限制为 2
```

第三个索引限制容量，这样第一次 append 就会扩容到新数组，**永远不会写回 original**——这是防御共享底层数组坑的惯用手段之一（另一种是 copy 出独立副本）。

**常见坑/易错点**

1. **以为数组传参能改原数组**：数组是值类型，函数里改的是副本，要传 `*[3]int` 指针。
2. **`append` 不接返回值**：`append(s, 6)` 结果丢失，必须写 `s = append(s, 6)`。
3. **修改子切片影响原切片**：`part := original[1:3]` 后 `part[0] = 200` 会改掉 `original[1]`。
4. **最隐蔽的坑：容量内的 append 悄悄覆盖原数组后续元素**——子切片容量够时不扩容，新值直接写进共享的底层数组。

**动手练习**

1. 创建切片 `s := []int{1, 2, 3, 4, 5}`，用三索引切片取 `s[2:4:4]`，append 一个 99，打印 `s` 验证它没被改动。（提示：对比不用第三索引时的结果。）
2. 写一个函数 `removeAt(s []int, i int) []int`，用 `copy` 删除下标 `i` 的元素并返回新切片。（提示：参照示例 4 的删除手法，注意最后长度减一。）

### 07_maps.go：map 映射

**这个文件带你认识什么**

学习 Go 的哈希表：`make` 与字面量两种初始化方式、`comma-ok` 判断键是否存在、`delete` 与 `clear`、故意随机化的遍历顺序及行序无关的验证思路、用 `map[T]struct{}` 实现 set，以及"map 并发不安全"的预警。

**运行命令与预期输出解读**

```powershell
go run 01-basics/07_maps.go
```

- **示例 1**：打印用 `make` 创建的成绩 map 和字面量创建的价格 map；读取 nil map 的键返回零值 0（安全），但**写 nil map 会 panic**（文件中以注释形式给出危险写法）。
- **示例 2**：comma-ok 判断 "Tom" 存在并打印年龄、"Nobody" 不存在；`delete` 删除 Tom 后打印；`clear`（Go 1.21+）清空整个 map 后长度为 0。
- **示例 3**：遍历四个城市的昵称 map——**每次运行输出顺序都可能不同**，这是 Go 故意随机化的；随后演示"行序无关验证"：不关心顺序，只统计非空昵称数量（输出 4）。
- **示例 4**：用 `map[string]struct{}` 给含重复元素的切片去重，打印去重后元素个数（3）；comma-ok 判断 "Go" 在集合中、"C++" 不在。
- **示例 5**：文字预告 map 并发不安全（多个 goroutine 同时读写会 fatal error 且无法 recover），打印单协程下读写完全安全的示例。

**关键代码讲解**

```go
if age, ok := ages["Tom"]; ok {
	fmt.Println("Tom 的年龄:", age)
}
```

**comma-ok 模式**：读取不存在的键会返回零值（int 是 0），只看值无法区分"键不存在"和"值真的是 0"。第二个返回值 `ok` 是布尔，明确表示键是否存在。

```go
var nilMap map[string]int
// nilMap["x"] = 1 // 这一行会 panic
```

只声明不初始化得到 **nil map**：读安全（返回零值），**写会 panic**。map 使用前必须 `make` 或用字面量初始化。

```go
set := make(map[string]struct{})
set[m] = struct{}{}
```

Go 没有内置 set，惯用法是 `map[T]struct{}`——空结构体占 0 字节，比 `map[T]bool` 更省内存；重复写入同一键自然去重，判断存在仍用 comma-ok。

**常见坑/易错点**

1. **写 nil map 会 panic**（读不会）——务必先 `make` 再写入。
2. **不用 comma-ok 区分"不存在"与"值为零值"**——`ages["Nobody"]` 返回 0，但 0 不代表某人真的 0 岁。
3. **依赖 map 遍历顺序**：Go 故意随机化，需要有序输出时先把 key 放入切片 `sort` 排序后再遍历；测试断言改用 len + 逐键 comma-ok 检查，不要按顺序拼接字符串比较。
4. **多 goroutine 同时读写同一个 map 会直接 fatal error 崩溃**，且无法用 recover 捕获；并发保护（sync.Mutex 等）属于中级阶段内容。

**动手练习**

1. 给定 `[]string{"a", "b", "a", "c", "b"}`，用 map 统计每个字符串出现次数并打印。（提示：value 用 int，读到就 +1。）
2. 把示例 3 的城市 map 按 key 排序后稳定输出。（提示：把 key 收集到切片，用 `sort.Strings` 排序——`sort` 是标准库——再按序取值。）

### 08_structs.go：结构体

**这个文件带你认识什么**

结构体是 Go 组织数据的核心方式。你将学会多种初始化方式、**值接收者与指针接收者的区别及选择标准**（Go 的"方法"就是绑定在类型上的函数）、匿名字段嵌入带来的方法提升（组合而非继承）、字段标签（struct tag）与 JSON 序列化，以及结构体何时能用 `==` 比较。

**运行命令与预期输出解读**

```powershell
go run 01-basics/08_structs.go
```

- **示例 1**：用四种方式初始化 `User`——字段名初始化、顺序初始化、部分字段（其余为零值）、先声明后逐个赋值，分别打印。
- **示例 2**：`Counter` 先调值接收者 `IncrementByValue`，余额/计数不变（改了副本）；再调指针接收者 `IncrementByPointer`，计数变为 1。
- **示例 3**：`Dog` 嵌入 `Animal`，直接调用提升来的 `Speak()` 打印"旺财 发出了叫声"；直接访问提升字段 `d.Name`。
- **示例 4**：`Product` 序列化为 JSON——键名按 tag 变小写、`Note` 字段因 `json:"-"` 被忽略、小写 `token` 字段不参与序列化；再反序列化一段 JSON 回结构体并用 `%+v` 打印。
- **示例 5**：两个字段全等的 `User` 用 `==` 比较为 true；含切片字段的 `Team` 不能用 `==`（编译错误，注释中给出），改用逐字段比较函数。

**关键代码讲解**

```go
func (c Counter) IncrementByValue()   { c.count++ } // 操作副本，原对象不变
func (c *Counter) IncrementByPointer() { c.count++ } // 操作原对象，修改生效
```

**接收者的选择是 Go 面试和日常开发的高频考点**。经验法则：方法要修改接收者 → 必须指针接收者；结构体很大拷贝成本高 → 指针接收者；同一类型的方法最好统一一种风格；只读小结构体用值接收者更安全。

```go
type Dog struct {
	Animal // 匿名字段嵌入：Dog 自动获得 Animal 的字段和方法
	Breed  string
}
```

嵌入是**组合**而非继承：`d.Speak()` 和 `d.Name` 是被"提升"的 Animal 成员，但 Animal 不知道 Dog 的存在，也不能用 Dog 替换需要 Animal 的地方。

```go
ID   int    `json:"id"`  // 序列化键名改为小写 id
Note string `json:"-"`   // "-" 表示序列化时忽略
```

struct tag 是写在字段后的字符串元数据，`encoding/json` 等包会读取它来控制序列化行为。

**常见坑/易错点**

1. **值接收者方法里修改字段不生效**——方法拿到的是副本；要修改原对象必须用指针接收者。
2. **同一类型混用值/指针接收者**会造成困惑，社区共识是统一风格。
3. **误以为嵌入是继承**：Go 没有继承体系，嵌入只是组合 + 方法/字段提升。
4. **含切片/map/函数字段的结构体不能用 `==`**，会编译报错；此时用 `reflect.DeepEqual`（性能差）或自写比较逻辑。
5. **顺序初始化 `User{"小红", 18, "上海"}` 必须写全字段且依赖字段顺序**，字段调整时极易出错，推荐字段名初始化。

**动手练习**

1. 给 `User` 添加一个指针接收者方法 `Birthday()`，使 Age 加一；再写一个值接收者版本对比调用后的差异。（提示：参照 Counter 的两个方法。）

### 09_pointers.go：指针

**这个文件带你认识什么**

指针是理解 Go 内存模型的钥匙：`&` 取地址、`*` 解引用、用指针参数实现"按引用"修改、`new` 函数、nil 指针的判空，最后回到接收者话题对比值/指针两种写法。学完后 08 文件里"接收者怎么选"会有更扎实的理解。

**运行命令与预期输出解读**

```powershell
go run 01-basics/09_pointers.go
```

- **示例 1**：打印 x 的值、p 保存的地址（**地址本身每次运行可能不同**，只看类型和指向关系）、`*p` 解引用得到 42；`*p = 100` 后 x 本身被改为 100；`%T` 打印 p 的类型 `*int`。
- **示例 2**：`swap(&a, &b)` 通过指针交换两个变量（1,2 → 2,1）；`doubleValue(n)` 传值改副本，n 不变；`doublePointer(&n)` 传地址，n 翻倍为 20。
- **示例 3**：`new(int)` 分配零值内存（指向 0），赋值后变 7；`new(Point)` 得到零值结构体指针，`pt.X = 3` 这种语法糖等价于 `(*pt).X`；字面量取地址 `&Point{X: 1, Y: 2}` 更常用。
- **示例 4**：`var p *int` 是 nil 指针，判空后安全跳过解引用；`findUser(2)` 返回 nil 走默认名字分支，`findUser(1)` 返回有效指针打印"小明"。
- **示例 5**：`Wallet` 值接收者存 50 后余额仍是 100（修改丢失）；指针接收者存 50 后余额变为 150。

**关键代码讲解**

```go
p := &x  // & 取变量地址，p 的类型是 *int
*p = 100 // * 解引用：通过指针修改，x 本身被改变
```

`*` 在**不同位置含义不同**：类型声明中 `*int` 表示"指针类型"；表达式中 `*p` 表示"解引用取值/赋值"。分清这两个语境是指针入门的关键。

```go
func swap(a, b *int) {
	*a, *b = *b, *a
}
```

**Go 只有一种传参方式：值传递**。传指针 = 把地址的副本传过去，函数内通过地址仍能修改调用方的变量，效果等同"按引用"。

```go
if p == nil {
	fmt.Println("p 是 nil 指针，跳过解引用（安全）")
}
```

对 **nil 指针解引用会 panic**（invalid memory address）。凡是"可能返回 nil"的函数（如示例中的 `findUser`），调用方务必先判空再解引用。

**常见坑/易错点**

1. **对 nil 指针解引用直接 panic**——解引用前永远先 `if p == nil`。
2. **混淆 `*` 的两种含义**：类型位置是"指针类型"，表达式位置是"解引用"。
3. **以为 Go 有引用传递**：没有，一切皆值传递，传的是地址的副本。
4. **值接收者方法里改字段不生效**（与 08 文件呼应）：钱包存钱的例子中修改悄悄丢失。

**动手练习**

1. 写一个函数 `reset(p *int)`，把它指向的整数归零，并在 main 中验证原变量被修改。（提示：函数体内 `*p = 0`。）

**关键代码讲解**

```go
runes := []rune(s)

```

**Go 字符串不可变**——`s[0] = 'H'` 无法编译。想"修改"要先转成 `[]rune`（或 ASCII 场景用 `[]byte`），改完再转回 string。处理含中文的字符串务必用 `[]rune`，否则一个汉字会被拆成 3 个字节。

```go
for i, r := range s { // range 自动按 UTF-8 解码
```

`range` 遍历字符串时每次得到一个**完整字符**（rune），但索引 `i` 是该字符的**起始字节下标**，不是字符序号——所以 "Go语言" 的索引是 0,1,4,7 而不是 0,1,2,3。需要"第几个字符"时请自己计数或先转 `[]rune`。

```go
var sb strings.Builder
sb.Grow(64) // 可选：预估容量，减少扩容
for _, w := range words {
	sb.WriteString(w)
}
```

循环里用 `s += x` 拼接每次都会产生新字符串（旧内容被拷贝），数据量大时非常浪费。`strings.Builder` 内部维护可增长缓冲区，是高效拼接的标准做法。

**常见坑/易错点**

1. **试图给字符串下标赋值** `s[0] = 'H'`：编译错误，字符串不可变。
2. **用 `len` 当字符数**：按字符数截断、限制输入长度等场景必须换算成 rune 数量（`len([]rune(s))` 或 `utf8.RuneCountInString`）。
3. **range 的下标是字节下标、不连续**：需要字符序号时自己计数。
4. **循环里 `+=` 拼字符串**：大量拼接时性能差，用 `strings.Builder`。
5. **单引号与双引号混用**：单引号是 rune 字面量（一个字符），双引号才是 string。

**动手练习**

## 六、自测题（5 题）

**第 1 题**：`:=` 和 `var` 声明变量有什么区别？下面代码哪行会编译报错，为什么？

```go
var x = 1
x := 2
```

**答案**：两处区别——① `:=` 只能用于函数内部，包级变量只能用 `var`；② 同一作用域内不能对已有变量重复 `:=`。上面第二行 `x := 2` 会报错 "no new variables on left side of :="，因为 `x` 已声明且左边没有新变量。另外 `:=` 一定带类型推断（不能写类型），而 `var` 可写可不写。

**第 2 题**：`rune` 和 `byte` 分别是什么类型的别名？遍历字符串 `"Go语言"` 时，为什么推荐 `for range` 而不是 `for i := 0; i < len(s); i++`？

**答案**：`rune` 是 `int32` 的别名，表示一个 Unicode 码点（一个字符）；`byte` 是 `uint8` 的别名，表示一个字节。UTF-8 下一个汉字占 3 字节，按下标遍历拿到的是单个 byte，汉字会被拆成 3 个无意义的数字；`for range` 会自动按 UTF-8 解码，每次得到一个完整字符。注意 range 的索引是起始字节下标（0,1,4,7），不是字符序号。

**第 3 题**：下面代码输出什么？为什么？

```go
original := []int{1, 2, 3, 4, 5}
part := original[1:3]
part = append(part, 999)
fmt.Println(original)
```

**答案**：输出 `[1 2 3 999 5]`。`part := original[1:3]` 与 `original` 共享同一个底层数组，且 `part` 的容量是 4（从起始位置起底层数组还有空间）。`append(part, 999)` 时 len(3) 未超过 cap(4)，不扩容，999 直接写入共享数组的下标 3，悄悄覆盖了原来的 4。防御手段：copy 出独立副本，或用三索引切片 `original[1:3:3]` 限制容量。

**第 4 题**：什么是 comma-ok 模式？下面代码有什么问题？

```go
ages := map[string]int{"Tom": 0}
age := ages["Jerry"]
fmt.Println("Jerry 的年龄是", age)
```

**答案**：comma-ok 指 `value, ok := m[key]` 的双返回值写法，`ok` 为 bool 表示键是否存在。上面代码的问题是：`Jerry` 不存在时 `age` 得到零值 0，打印出"Jerry 的年龄是 0"，与"Tom 真的 0 岁"无法区分。正确写法：

```go
if age, ok := ages["Jerry"]; ok {
	fmt.Println("Jerry 的年龄是", age)
} else {
	fmt.Println("Jerry 不在 map 中")
}
```

**第 5 题**：下面程序的输出顺序是什么？`defer` 打印的 `x` 是几？

```go
func demo() {
	x := 1
	defer fmt.Println("A", x)
	defer fmt.Println("B")
	x = 100
	fmt.Println("C")
}
```

**答案**：输出依次为 `C`、`B`、`A 1`。规则：① 函数体正常输出 `C` 最先打印；② 多个 defer 按 LIFO（后进先出）执行，后注册的 `B` 先执行；③ defer 的参数在**注册时**就已求值，所以 `A` 打印的是注册时的 `x=1`，不是后来改的 100。若想拿到最新值，应传闭包：`defer func() { fmt.Println("A", x) }()`。
